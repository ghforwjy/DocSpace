
# EasyDocs 文档版本管理逻辑

## 一句话总结

**EasyDocs 不是每次保存都创建新版本，而是根据情况判断！**

---

## 一、什么时候会创建新版本？（说人话）

### 场景1：正常编辑保存（最常见）
→ **每次保存都会创建新版本**
- 版本号 `Version++`
- 版本组 `VersionGroup++`
- 数据库中保存为新记录

### 场景2：强制保存（Forcesave）
→ **看配置，可能是新版本，也可能覆盖当前版本**
- 如果是用户强制保存 + 系统配置允许：创建新版本
- 其他情况：覆盖当前版本（不创建新版本）

### 场景3：新创建的文档
→ **如果是从模板创建的，要看有没有真的修改过
- 如果修改了才创建新版本
- 如果没修改（跟模板一样：不创建新版本

---

## 二、版本号和版本组的区别？

### 版本号（Version）
- **每次保存都会增加**
- 像：1, 2, 3, 4, 5...
- 每个版本号对应一个独立记录

### 版本组（VersionGroup）
- **是分组用的**，用于版本合并
- 像：2, 3, 4...（通常比版本号大1或相同）
- **可以理解为：大版本号**

---

## 三、版本组怎么用？什么时候会变化？

### 版本组变化的3种情况：

| 情况 | 版本组怎么变 | 位置 |
|------|-------------|------|
| **1. 正常保存文件** | `VersionGroup++` | EntryManager.cs:1359 |
| **2. 新文档首次修改（从模板）** | 如果修改了，`VersionGroup++` | EntryManager.cs:1374 |
| **3. 调用合并版本API（ContinueVersion=true）** | 后面的版本的VersionGroup-- | FileQueries.cs:744 |

---

## 四、合并版本API（专门接口）

### 1. API 接口
```
PUT /api/2.0/files/file/{fileId}/history
```

### 2. 请求参数
```json
{
  "file": {
    "version": 3,           // 从哪个版本开始合并
    "continueVersion": true // true=合并版本，false=恢复到这个版本
  }
}
```

### 3. 合并版本的原理（人话）

**假设现在版本是 v1, v2, v3, v4, v5：**
- v1: Version=1, VersionGroup=2
- v2: Version=2, VersionGroup=3  
- v3: Version=3, VersionGroup=4
- v4: Version=4, VersionGroup=5
- v5: Version=5, VersionGroup=6

**调用合并API（version=3, continueVersion=true）后：**
- 把 v3 **之后** 所有版本的 VersionGroup 都 **减 1**
- v4: VersionGroup 5 → 4
- v5: VersionGroup 6 → 5
- 意思是：v3、v4、v5 现在属于**同一组**了，可以合并显示

## 五、数据库怎么存的？

| 字段 | 作用 |
|------|------|
| **Version | 版本号（每次+1） |
| **VersionGroup | 版本组（用于合并版本） |
| **CurrentVersion | 是否当前版本 |
| **Id | 文件ID |
| **TenantId | 租户ID |

**主键是：TenantId + Id + Version  
意思是：**每个文件的每个版本都是一条独立记录**

## 六、版本增加的具体代码逻辑

在 `/server/products/ASC.Files/Core/Utils/EntryManager.cs` → `SaveEditingAsync` 方法（1296行开始）：

```csharp
// 关键代码：
if (file.Forcesave != ForcesaveType.None)
{
    // 强制保存模式
    if (file.Forcesave == ForcesaveType.User && 配置允许 || 加密文件)
    {
        file.Version++;  // 创建新版本
    }
    else
    {
        replaceVersion = true;  // 覆盖当前版本，不新建
    }
}
else
{
    // 正常保存
    if (file.Version != 1 || 不是模板文件)
    {
        file.VersionGroup++;
    }
    else
    {
        // 检查是不是真的从模板修改了
        if (文件内容 != 模板)
        {
            file.VersionGroup++;
        }
    }
    file.Version++;  // 版本号+1
}
```

## 七、版本相关的API功能

| API接口 | 功能 |
|---------|------|
| `GET /file/{fileId}/edit/history` | 获取编辑历史 |
| `GET /file/{fileId}/history` | 获取所有版本列表 |

## 八、合并版本API调用示例

### JavaScript 示例
```javascript
async function mergeVersions(fileId, fromVersion) {
  const response = await fetch(
    `/api/2.0/files/file/${fileId}/history`,
    {
      method: 'PUT',
      headers: {
        'Content-Type': 'application/json'
      },
      body: JSON.stringify({
        file: {
          version: fromVersion,
          continueVersion: true  // true=合并，false=恢复
        }
      })
    }
  );
  return await response.json();
}

// 使用：从版本3开始合并
mergeVersions(123, 3);
```

## 九、完整调用链路

1. **前端保存** → 调用 `FilesController.UpdateFileStreamAsync`
