# DocSpace 文档管理机制详解

## 一、系统定位与核心功能

DocSpace 是一个**企业级文档协作平台**，类似于企业版的"文档库 + 协作空间"。它解决了企业文档管理的三大核心问题：

| 核心问题 | DocSpace 解决方案 |
|---------|------------------|
| 文档杂乱无章 | **Room（房间）** 作为文档容器，按项目/部门/场景组织文档 |
| 权限控制复杂 | **多级权限体系**，支持用户组、外部链接、密码保护等 |
| 文档分享困难 | **多种分享机制**，支持内部分享和外部链接分享 |

## 二、文档存储结构

### 2.1 物理存储（数据库）

```
files_file 表（文件表）
├── id, title, content_length  -- 基本信息
├── parent_id                   -- 所属文件夹
├── create_by, modified_by      -- 创建者/修改者
├── version, version_group      -- 版本控制
└── encrypted, forcesave        -- 加密、强制保存

files_folder 表（文件夹表）
├── id, title                   -- 基本信息
├── parent_id                   -- 父文件夹
├── folder_type                 -- 文件夹类型（区分普通文件夹和Room）
└── create_by, modified_by      -- 创建者/修改者

files_room_settings 表（房间设置）
├── room_id                     -- 房间ID
├── private                     -- 是否私有
├── quota                       -- 空间配额限制
├── watermark                   -- 水印设置
└── deny_download               -- 禁止下载

files_security 表（权限表）
├── entry_id, entry_type        -- 被授权的文件/文件夹
├── subject, subject_type       -- 被授权的用户/组/链接
├── share                       -- 权限级别
└── options                     -- 额外选项（密码/过期时间等）
```

## 三、Room（房间）详解

### 3.1 什么是 Room？

**Room 是 DocSpace 的核心概念**，它是一个**带权限的文档容器**。

```
普通文件夹：只是存放文件，没有权限概念
Room：       既是文件夹，又自带一套完整的权限体系
```

**Room 的特点：**
1. **独立的权限体系**：Room 内的文档不继承外部权限，由 Room 自己管理
2. **安全强化选项**：可设置水印、禁止下载、访问密码、过期时间
3. **配额控制**：可限制 Room 的最大存储空间
4. **多种类型**：针对不同业务场景（协作、安全、表单、公开等）

### 3.2 Room 类型与业务场景

| Room 类型 | FolderType 值 | 业务场景 | 核心特点 |
|-----------|--------------|---------|---------|
| **CustomRoom** | 19 | 通用项目协作 | 支持多种权限，适合大多数业务场景 |
| **EditingRoom** | 16 | 实时文档编辑 | 支持多人同时编辑同一文档 |
| **FillingFormsRoom** | 15 | 表单收集 | 外部用户填写表单，提交后不可修改 |
| **PublicRoom** | 22 | 信息公开 | 完全公开，无需登录即可查看 |
| **VirtualDataRoom** | 29 | 机密文件共享 | 最高安全级别，支持水印追踪 |
| **AiRoom** | 31 | AI 辅助问答 | 基于 AI 的文档理解和问答 |

---

### 3.3 CustomRoom（自定义房间）【最常用】

**用途**：日常项目协作、部门文档共享

**典型场景**：
- "市场部2024年计划"房间
- "产品需求"房间
- "团队知识库"房间

**可用权限**：
| 主体 | 可授予权限 |
|-----|----------|
| 用户 | 房间管理员、内容创建者、编辑、审阅、评论、只读 |
| 用户组 | 内容创建者、编辑、审阅、评论、只读 |
| 外部链接 | 只读（可设置密码和过期时间）|

**特殊设置**：
- ✅ 可设置访问密码
- ✅ 可设置过期时间
- ✅ 可设置空间配额
- ❌ 水印默认关闭

**示例**：
```
场景：市场部需要创建一个"产品发布会"项目房间

1. 创建 CustomRoom，命名为"产品发布会"
2. 设置空间配额：1GB
3. 授予权限：
   - 张三（项目经理）→ 房间管理员
   - 李四、王五（团队成员）→ 内容创建者
   - 外部合作方 → 只读（带密码保护）
4. 市场部全员 → 评论权限
```

---

### 3.4 EditingRoom（编辑协作房间）

**用途**：需要多人实时协作编辑文档

**典型场景**：
- 团队共同撰写报告/方案
- 多人编辑同一份合同
- 协作编写代码文档

**与 CustomRoom 的区别**：
- 支持**实时协作编辑**（类似 Google Docs）
- 外部链接权限**更严格**（不支持审阅、评论等）
- 适合需要"多人同时编辑"的高频协作场景

**可用权限**：
| 主体 | 可授予权限 |
|-----|----------|
| 用户 | 房间管理员、内容创建者、编辑、审阅、评论、只读 |
| 用户组 | 内容创建者、编辑、审阅、评论、只读 |
| 外部链接 | 只读（不支持审阅/评论）|

**特殊设置**：
- ✅ 支持实时协作编辑
- ✅ 可设置空间配额
- ❌ 外部链接不支持评论/审阅

**示例**：
```
场景：法务部需要多人同时编辑一份法律合同

1. 创建 EditingRoom，命名为"XX合同-协作编辑"
2. 授予权限：
   - 律师A、律师B、律师C → 编辑权限
   - 客户（外部）→ 只读（带过期时间：7天）
3. 各方可以同时打开文档，实时看到彼此的修改
```

---

### 3.5 FillingFormsRoom（表单填写房间）

**用途**：收集外部人员填写的表单数据

**典型场景**：
- 活动报名表
- 员工满意度调查
- 客户反馈表
- 订单/申请表

**核心机制**：
- 外部用户通过链接**只读查看 + 填写表单**
- 提交后**无法修改**自己的答案
- 管理员可以**导出所有提交数据**

**可用权限**：
| 主体 | 可授予权限 |
|-----|----------|
| 用户 | 房间管理员、内容创建者、填写表单、只读 |
| 用户组 | 内容创建者、填写表单、只读 |
| 外部链接 | **填写表单**（只能填表，不能查看其他内容）|

**特殊设置**：
- ✅ 外部链接只能**填写表单**，不能查看其他文件
- ✅ 提交后自动记录提交者信息
- ✅ 可设置表单截止时间

**示例**：
```
场景：HR 需要收集员工2024年度目标

1. 创建 FillingFormsRoom，命名为"2024年度目标收集"
2. 上传表单模板（Excel/表单格式）
3. 发布外部链接（外部用户无需登录）
4. 员工点击链接 → 填写表单 → 提交
5. 提交后，员工无法再修改自己的答案
6. HR 在后台导出所有员工的填写结果
```

---

### 3.6 PublicRoom（公开房间）

**用途**：对所有人公开的信息发布

**典型场景**：
- 公司新闻公告
- 产品资料下载
- 公开的政策文件
- 营销宣传材料

**核心特点**：
- **无需登录**，任何人可访问
- 可设置**不需要密码**的公开链接
- 外部链接**默认不能修改**，只能查看/下载

**可用权限**：
| 主体 | 可授予权限 |
|-----|----------|
| 用户 | 房间管理员、内容创建者、无权限 |
| 用户组 | 内容创建者、无权限 |
| 外部链接 | **只读**（不需要密码，不需要登录）|

**特殊设置**：
- ✅ 可设置**无密码**的公开链接
- ✅ 外部用户**无需登录**即可访问
- ❌ 不支持评论/审阅权限
- ❌ 外部链接不支持过期时间（永久有效）

**示例**：
```
场景：市场部发布新产品宣传资料

1. 创建 PublicRoom，命名为"2024新品发布"
2. 上传宣传资料（PDF、图片、视频等）
3. 生成公开链接，放在官网/公众号
4. 任何人都可以访问查看和下载（无需登录）
```

---

### 3.7 VirtualDataRoom（虚拟数据房间，VDR）

**用途**：高机密文件的分享与审阅

**典型场景**：
- 融资路演材料
- 并购尽职调查
- 招投标文件
- 知识产权资料
- 法律诉讼材料

**核心特点**：
- **最高安全级别**
- 支持**水印追踪**（每个下载者都有水印标记）
- 可**禁止下载**（只能在线查看）
- 支持**空间配额**精确控制

**可用权限**：
| 主体 | 可授予权限 |
|-----|----------|
| 外部链接 | 只读（必须带密码）|

**特殊设置**：
- ✅ **强制水印**：下载时自动添加下载者信息水印
- ✅ **禁止下载**：只能在线查看，不能下载
- ✅ **强制密码**：外部链接必须设置密码
- ✅ **空间配额**：可限制房间的最大存储量
- ✅ **访问日志**：详细记录每个访问者的行为

**示例**：
```
场景：投资经理需要向潜在投资人展示融资材料

1. 创建 VirtualDataRoom，命名为"XX公司融资材料-VDR"
2. 启用水印功能（显示：公司名 + 投资人姓名 + 下载时间）
3. 启用禁止下载功能（只能在线查看）
4. 设置强制密码和过期时间（7天）
5. 发送链接给投资人：投资人必须输入密码，在线查看，
   每次下载都会带有水印标记，便于追踪泄露源头
```

### 3.8 AiRoom（AI 房间）

**用途**：基于 AI 的文档理解与智能问答

**典型场景**：
- 合同条款问答
- 文档内容总结
- 政策文件解读
- 知识库智能搜索

**核心特点**：
- 内置 AI 助手，可以**理解文档内容**
- 用户可以**用自然语言提问**，AI 回答基于文档内容
- 支持**多文档联合理解**

**特殊设置**：
- ✅ AI 助手基于房间内的文档进行问答
- ✅ 访客（Guest）不能成为房间管理员或内容创建者
- ✅ 支持文档的向量化处理（用于语义搜索）

**示例**：
```
场景：法务部创建合同知识库

1. 创建 AiRoom，命名为"合同知识库"
2. 上传所有历史合同文档
3. 系统自动对文档进行 AI 处理（向量化）
4. 用户提问："这个合同里的违约金条款是什么？"
5. AI 基于文档内容给出回答，并标注来源
```

## 四、权限体系

### 4.1 权限级别（从高到低）

| 权限值 | 名称 | 说明 |
|-------|------|------|
| 9 | RoomManager | 房间管理员，拥有最高权限 |
| 11 | ContentCreator | 内容创建者，可以上传/编辑 |
| 10 | Editing | 编辑，可以修改内容 |
| 5 | Review | 审阅，可以审阅但不能修改 |
| 6 | Comment | 评论，可以添加评论 |
| 7 | FillForms | 填写表单，用于表单房间 |
| 2 | Read | 只读，可以查看和下载 |
| 3 | Restrict | 受限，仅创建者可见 |
| 0 | None | 无权限 |

**权限继承规则**：
```
普通文件夹：子文件继承父文件夹权限
Room：      权限独立，不继承外部权限
```

### 4.2 权限主体类型

| 主体类型 | 说明 | 典型场景 |
|---------|------|---------|
| User | 指定用户 | 授予某个具体用户权限 |
| Group | 用户组 | 授予"市场部"组所有成员权限 |
| ExternalLink | 外部链接 | 生成给外部合作方的访问链接 |
| PrimaryExternalLink | 主外部链接 | Room 只能有一个主链接 |
| InvitationLink | 邀请链接 | 用于 Room 邀请新成员 |

### 4.3 外部链接的数量限制

| Room 类型 | 主链接(PrimaryExternalLink) | 额外链接(ExternalLink) |
|----------|---------------------------|----------------------|
| CustomRoom | 1 | 5 |
| PublicRoom | 1 | 5 |
| FillingFormsRoom | 1 | 0 |
| EditingRoom | 0 | 6 |
| VirtualDataRoom | 0 | 6 |
| AiRoom | 0 | 6 |

## 五、分享机制

### 5.1 内部分享 vs 外部分享

```
┌─────────────────────────────────────────────────────────┐
│                    内部分享                              │
│  分享者 ──────→ 用户/用户组                              │
│  - 需要是系统用户                                        │
│  - 可授予任意权限级别                                     │
│  - 可撤销权限                                           │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│                    外部分享                              │
│  分享者 ──────→ 链接 ──────→ 任意人                       │
│  - 不需要是系统用户（ExternalLink）                        │
│  - 权限受 Room 类型限制                                   │
│  - 可设置密码、过期时间                                   │
└─────────────────────────────────────────────────────────┘
```

### 5.2 链接安全选项

| 选项 | 说明 | 可用场景 |
|-----|------|---------|
| **Internal** | 内部链接，访问者必须登录 | 所有 Room |
| **Password** | 密码保护，访问者需输入密码 | 所有 Room |
| **ExpirationDate** | 过期时间，超过后链接失效 | CustomRoom, EditingRoom, VDR, AiRoom |
| **DenyDownload** | 禁止下载，只能在线查看 | VirtualDataRoom（强制）|
| **Watermark** | 水印追踪，记录下载者信息 | VirtualDataRoom（强制）|

### 5.3 链接访问验证流程

```
用户点击外部链接
        ↓
    ┌───────────────────────┐
    │ 1. 检查链接是否过期    │──是──→ 返回"链接已过期"
    └───────────────────────┘
        ↓否
    ┌───────────────────────┐
    │ 2. 检查是否需要登录    │──是──→ 返回"请先登录"
    └───────────────────────┘
        ↓否
    ┌───────────────────────┐
    │ 3. 检查是否需要密码    │──是──→ 显示密码输入框
    └───────────────────────┘
        ↓否
    ┌───────────────────────┐
    │ 4. 检查文档状态        │──归档/删除──→ 返回"文件不存在"
    └───────────────────────┘
        ↓正常
    ┌───────────────────────┐
    │ 5. 记录访问日志        │ （仅 VDR）
    └───────────────────────┘
        ↓
    ┌───────────────────────┐
    │ 6. 返回文档内容        │
    └───────────────────────┘
```

## 七、数据库关键表结构

### files_folder（文件夹表）

```sql
CREATE TABLE files_folder (
    id INT PRIMARY KEY,           -- 文件夹ID
    parent_id INT,                -- 父文件夹ID
    title VARCHAR(400),           -- 名称
    folder_type INT,              -- 类型（0=普通, 19=CustomRoom, 29=VDR等）
    create_by GUID,               -- 创建者
    create_on DATETIME,           -- 创建时间
    modified_by GUID,             -- 修改者
    modified_on DATETIME,         -- 修改时间
    folders_count INT,             -- 子文件夹数
    files_count INT,               -- 子文件数
    counter BIGINT                 -- 占用空间
);
```

### files_room_settings（房间设置表）

```sql
CREATE TABLE files_room_settings (
    room_id INT PRIMARY KEY,     -- 房间ID
    tenant_id INT,                -- 租户ID
    private BOOL,                 -- 是否私有
    quota BIGINT,                 -- 空间配额（-2表示无限制）
    watermark JSON,                -- 水印设置
    deny_download BOOL,           -- 禁止下载
    color CHAR(6),                -- 主题色
    indexing BOOL                 -- 是否允许搜索引擎索引
);
```

### files_security（权限表）

```sql
CREATE TABLE files_security (
    id INT PRIMARY KEY,
    entry_id INT,                 -- 文件/文件夹ID
    entry_type INT,               -- 条目类型（1=文件, 2=文件夹）
    subject GUID,                 -- 被授权者ID（用户/组/链接）
    subject_type INT,             -- 授权类型（0=用户, 1=外部链接, 2=组）
    share INT,                    -- 权限级别
    options JSON                   -- 额外选项（密码、过期时间等）
);
```
