# 文档服务配置与编辑器调用完整流程

## 1. 概述

本文档完整描述 DocSpace 系统中 **文档服务的配置流程** 和 **文档编辑器调用流程**，涵盖从管理员配置 DocumentServer，到用户打开文档进行编辑的完整链路。

**目标**：让环境检查思路清晰、环境配置准备充分、整个配置过程流畅正确，保证以后新搭建都能一次完成。

## 5. 流程一：文档服务配置

### 5.1 配置概述

管理员在 DocSpace 设置界面中配置 DocumentServer 的连接信息，包括：
- DocumentServer URL（**对外访问地址**，浏览器使用）
- 内部 URL（**容器间访问地址**，.NET 后端使用）
- Portal URL（**回调地址**，DocumentServer 回调 DocSpace 用）
- JWT 密钥（用于请求签名验证）
- 授权头名称
- SSL 验证开关

### 5.2 三种 URL 的用途与区别

> **⚠️ 核心概念**：DocumentServer 配置中有三种 URL，分别用于不同的场景：

| URL 类型 | 配置 key | 用途 | 正确填写 |
|---------|---------|------|----------|
| **docServiceUrl** | Public | 浏览器加载 DocumentServer API | 必须是可以从浏览器访问的地址 |
| **docServiceUrlInternal** | Internal | .NET 后端访问 DocumentServer | Docker 网络内部地址 |
| **docServiceUrlPortal** | Portal | DocumentServer 回调 DocSpace | DocumentServer 可以访问的地址 |

```
┌─────────────────────────────────────────────────────────────────────┐
│                         三种 URL 用途说明                            │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  用户浏览器                                                           │
│      │                                                               │
│      │ ① 加载 DocsAPI (api.js, preload.html)                         │
│      │    from docServiceUrl (Public)                                │
│      ▼                                                               │
│  http://xxx/ds-api/  ←─── docServiceUrl (浏览器可访问)               │
│      │                                                               │
│      │ ② 编辑器 WebSocket 连接                                       │
│      │    to docServiceUrl (Public)                                   │
│      ▼                                                               │
│  http://xxx/ds-api/  ←─── docServiceUrl (浏览器可访问)               │
│                                                                      │
│  ────────────────────────────────────────────────────────────────   │
│                                                                      │
│  .NET 后端                                                           │
│      │                                                               │
│      │ ③ 下载文档、上传编辑结果                                       │
│      │    to docServiceUrlInternal (Internal)                        │
│      ▼                                                               │
│  http://onlyoffice-document-server:80/  ←─── docServiceUrlInternal  │
│                                                                      │
│  ────────────────────────────────────────────────────────────────   │
│                                                                      │
│  DocumentServer                                                      │
│      │                                                               │
│      │ ④ 回调 DocSpace (通知保存结果等)                              │
│      │    to docServiceUrlPortal (Portal)                             │
│      ▼                                                               │
│  http://onlyoffice-router:8092/  ←─── docServiceUrlPortal           │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### 5.6 网络上下文说明

| 上下文 | localhost 指向 | 说明 |
|--------|---------------|------|
| 宿主机浏览器 | 宿主机本身 | 用户访问 DocSpace 的入口 |
| .NET 容器内 | .NET 容器本身 | 无法访问其他容器 |
| DocumentServer 容器内 | DocumentServer 容器本身 | 无法访问 DocSpace |
| Router 容器内 | Router 容器本身 | 可以访问 Docker 网络内其他容器 |

**结论**：
- 在 Docker 网络中，**不要使用 `localhost`**
- 所有容器间通信必须使用 **Docker 网络地址**
- 浏览器访问的地址必须是 **nginx 代理的地址**

## 6. 流程二：Nginx 路由配置（关键）

### 6.1 为什么需要 /ds-api/ 路由

> **问题**：DocumentServer 运行在 Docker 容器内，其内部地址（如 `onlyoffice-document-server:80`）对浏览器不可见。

**解决方案**：通过 nginx 代理将 `/ds-api/` 路径转发到 DocumentServer。

### 6.2 Nginx 路由配置

在 `/home/ubuntu/EasyDocs/DocSpace/buildtools/config/nginx/onlyoffice.conf` 中添加：

```nginx
location /ds-api/ {
    rewrite /ds-api/(.*) /$1 break;
    proxy_pass http://onlyoffice-document-server:80/;
    proxy_redirect off;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $proxy_connection;
    proxy_set_header Host $http_host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $proxy_x_forwarded_proto;
    add_header Content-Security-Policy "default-src *; script-src * 'unsafe-inline' 'unsafe-eval'; script-src-elem * 'unsafe-inline'; img-src * data:; style-src * 'unsafe-inline' data:; font-src * data:; frame-src * ascdesktop:; object-src; connect-src * ascdesktop:;";
}
```

**关键配置说明**：

| 配置项 | 说明 |
|--------|------|
| `rewrite /ds-api/(.*) /$1 break` | 去掉 `/ds-api/` 前缀，保留剩余路径 |
| `proxy_pass http://onlyoffice-document-server:80/` | 转发到 DocumentServer |
| `proxy_http_version 1.1` | 必须使用 HTTP/1.1 |
| `proxy_set_header Upgrade $http_upgrade` | **支持 WebSocket** |
| `proxy_set_header Connection $proxy_connection` | **支持 WebSocket** |
| `add_header Content-Security-Policy` | 宽松 CSP，允许加载 DocumentServer 资源 |

### 6.3 部署 Nginx 配置


#### 步骤4：getData API 调用

**文件**: `client/packages/doceditor/src/utils/actions.ts`

```typescript
export async function getData(
    fileId: string,
    version?: string,
    doc?: string,
    action?: ActionType,
    share?: string,
    editorType?: string,
) {
    const view = action === "view";

    const searchParams = new URLSearchParams();
    if (action && availableActions[action]) searchParams.append(action, "true");
    if (version) searchParams.append("version", version);
    if (doc) searchParams.append("doc", doc);
    if (share) searchParams.append("share", share);
    if (editorType) searchParams.append("editorType", editorType);

    // 并行调用三个API
    const [config, user, settings] = await Promise.all([
        openEdit(fileId, searchParams.toString(), share),  // 获取编辑器配置
        getUser(share),                                    // 获取用户信息
        getSettings(share),                                // 获取系统设置
    ]);

    return { config, user, settings, successAuth: !!user };
}
```

#### 步骤5：openEdit 调用后端 API

```typescript
export async function openEdit(
    fileId: number | string,
    searchParams: string,
    share?: string,
) {
    // 调用 GET /api/2.0/files/file/{fileId}/openedit
    const [getConfig] = await createRequest(
        [`/files/file/${fileId}/openedit?${searchParams}`],
        [share ? ["Request-Token", share] : ["", ""]],
        "GET",
        undefined,
    );

    const res = await fetch(getConfig);
    const config = await res.json();

    if (res.ok) {
        config.response.editorUrl = config.response.editorUrl.replace(REPLACED_URL_PATH, "");
        return { ...config.response };
    }

    return error;
}
```

#### 步骤7：DocumentServiceHelper 生成配置

```csharp
public async Task<(File<T> File, Configuration<T> Configuration, bool LocatedInPrivateRoom)> GetParamsAsync<T>(
    T fileId,
    int version,
    bool editPossible,
    bool tryEdit,
    bool tryCoAuthoring,
    bool fillFormsPossible
)
{
    // 1. 获取文件信息
    var (file, lastVersion) = await GetCurFileInfoAsync(fileId, version);

    // 2. 检查用户权限
    var rightToEdit = rightToEdit && (await fileSecurity.CanEditAsync(file));

    // 3. 生成文档唯一key (用于Document Server缓存)
    var docKey = DocumentService.GenerateRevisionId(...);

    // 4. 获取文档下载地址
    var docUri = await fileStorageService.GetPreSignedUriAsync(file.Id);

    // 5. 构建配置
    Configuration = new Configuration<T>
    {
        Document = new Document<T>
        {
            Key = docKey,
            Url = docUri,
            Title = file.Title,
            FileType = file.Exst
        },

        EditorUrl = GetDocServiceUrl()  // Document Server 地址

}
```

## 9.5 Standalone 模式 vs Server Edition 模式

### 9.5.1 两种模式的本质区别

DocSpace 根据 `core.base-domain` 配置判断运行模式：

```csharp
// CoreConfiguration.cs
public bool Standalone => _standalone ??= Basedomain == "localhost";
```

| 模式 | Standalone 值 | 判断条件 | 典型场景 |
|------|---------------|----------|----------|
| **Standalone 模式** | `true` | `core.base-domain == "localhost"` | 单机部署，开发测试 |
| **Server Edition 模式** | `false` | `core.base-domain != "localhost"` | 集群部署，生产环境 |

### 9.5.2 两种模式对配置保存的影响

```csharp
// FilesLinkUtility.SetUrlSettingAsync - 保存 DocumentServer 配置
if (!_coreBaseSettings.Standalone)
{
    throw new NotSupportedException("Method for server edition only.");
}
// 只有 Standalone=true 时才允许保存配置到数据库
```

| 功能 | Standalone 模式 | Server Edition 模式 |
|------|-----------------|---------------------|
| 配置保存到数据库 | ✅ 支持 | ❌ 不支持（抛异常） |
| 配置读取优先级 | 数据库优先 | 只能使用配置文件 |

### 9.5.3 两种模式对配置读取的影响

```csharp
// FilesLinkUtility.GetUrlSettingAsync - 读取 DocumentServer 配置
if (_coreBaseSettings.Standalone)
{
    value = _coreSettings.GetSetting(key);  // 从数据库读取
}
if (string.IsNullOrEmpty(value))
{
    value = GetDefaultUrlSetting(key);  // 数据库为空则使用配置文件默认值
}
```

| 模式 | 配置读取来源 | 说明 |
|------|-------------|------|
| **Standalone** | 数据库优先 | 如果数据库为空，使用 `appsettings.json` 默认值 |
| **Server Edition** | 仅配置文件 | 直接使用 `appsettings.json` 配置 |

### 9.5.4 当前系统模式判断

检查当前 `core.base-domain` 配置：

```bash
docker exec onlyoffice-dotnet-services cat /app/onlyoffice/config/appsettings.json | grep base-domain
```

**当前配置**：`core.base-domain = "localhost"` → **Standalone 模式**

### 9.5.5 模式切换注意事项

**注意**：如果之前是 Standalone 模式，数据库中存储了配置，后来把 `core.base-domain` 改成非 localhost 值：
- 系统会切换到 Server Edition 模式
- `SetUrlSettingAsync` 会抛异常，**配置无法保存**
- 但之前数据库中的旧配置仍然存在，可能导致混淆

**建议**：
1. 生产环境建议使用 Server Edition 模式（`core.base-domain` 设置为实际域名）
2. Standalone 模式下，前端配置页面可以保存配置到数据库
3. Server Edition 模式下，只能通过修改 `appsettings.json` 配置文件

## 13. 已知问题与解决方案

### 13.1 ERR_NAME_NOT_RESOLVED 错误 ✅ 已解决

**问题描述**：
```
Failed to load resource: net::ERR_NAME_NOT_RESOLVED
error load DocsAPI from http://onlyoffice-document-server:80
```

**根本原因**：
- 配置中的 `docServiceUrl` 被设置为 `http://onlyoffice-document-server:80/`
- `onlyoffice-document-server` 是 Docker 内部主机名，浏览器无法解析

**解决方案**：
1. 添加 nginx `/ds-api/` 路由代理到 DocumentServer
2. 将 `docServiceUrl` 配置为 `http://<domain>:<port>/ds-api/`
3. 重启 .NET 容器清除配置缓存

**修复时间**：2026-04-14

### 13.2 WebSocket 400 错误 ✅ 已解决

**问题描述**：
```
WebSocket connection to 'ws://xxx/ds-api/9.3.1-.../doc/...' failed:
Error during WebSocket handshake: Unexpected response code: 400
```

**根本原因**：
- nginx 配置缺少 WebSocket 支持
- 没有正确配置 `Upgrade` 和 `Connection` headers

**解决方案**：
在 nginx location 配置中添加：
```nginx
proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection $proxy_connection;
```

### 13.3 .NET 容器配置缓存 ✅ 已解决

**问题描述**：
- 更新 DocumentService 配置后，API 返回 200 但配置未生效

**根本原因**：
- .NET 容器缓存了配置
- 需要重启容器才能清除缓存

**解决方案**：
```bash
docker restart onlyoffice-dotnet-services
```

### 13.4 DocumentServer 与 DocSpace URL 配置混淆 ✅ 已解决

**问题描述**：
- 误将内部 URL（`onlyoffice-document-server:80`）当作外部 URL 使用
- 导致浏览器无法访问

**正确配置原则**：

- `docServiceUrlInternal` (Internal)：Docker 网络内部地址
- `docServiceUrlPortal` (Portal)：DocumentServer 能访问的地址

### 13.5 前端设置导致配置错误 ✅ 已解决

**问题描述**：
- 通过前端配置页面保存 DocumentServer 设置时，配置无法正确保存
- 或者保存后文档编辑器无法加载，报错 `Error: An unexpected error occurred`

**根本原因**：
1. 前端配置保存 API 需要 `EditPortalSettings` 权限，未认证的请求不会保存配置
2. 配置实际保存在数据库 `core_settings` 表中，但存储的是**加密值**
3. 如果数据库中存储的加密值解密失败，系统会回退到 `appsettings.json` 默认值

**排查发现**：
- API 返回 200 但配置未实际保存（未认证）
- 数据库中的 `DocKey_public` 等值是加密的
- `core.base-domain = "localhost"` 导致系统判断为 `Standalone` 模式，优先从数据库读取

**解决方案**：
1. 清空数据库中的错误配置：`DELETE FROM core_settings WHERE id IN ('DocKey_public', ...)`
2. 重启 .NET 容器使配置生效

**修复命令**：
```bash
# 清空数据库配置
docker exec onlyoffice-mysql-server mysql -uonlyoffice_user -ponlyoffice_pass docspace -e "
DELETE FROM core_settings WHERE id IN ('DocKey_public', 'DocKey_secret:value', 'DocKey_secret:header');
"

# 重启服务
docker restart onlyoffice-dotnet-services
```

### 13.6 文件内容与扩展名不匹配 ✅ 已解决

**问题描述**：
```
ONLYOFFICE Document Editor reports an error: code -85, description 打开文件时出错<br>文件内容与文件扩展名不匹配。
```

**根本原因**：
1. nginx `/cache` 路由指向 `onlyoffice-node-services:5009`
2. **node-services 不监听 5009 端口**
3. 导致 `Connection refused`，nginx 返回 500 Error HTML
4. DocumentServer 收到 HTML 而不是二进制文件

**解决方案**：
修改 nginx `/cache` 路由指向正确的服务：
```nginx
location ~* ^/cache/ {
    proxy_pass http://onlyoffice-document-server:80;
    proxy_redirect off;
}
```

**修复时间**：2026-04-15

**详细分析**：见 [ISSUE-013-补充-文件下载流程与cache路由分析.md](../问题排查记录/ISSUE-013-补充-文件下载流程与cache路由分析.md)

## 16. 重要发现与最佳实践

### 16.1 登录 API 路径

> ⚠️ **重要**：DocSpace 的登录 API 路径是 `/api/2.0/authentication`，而不是 `/api/2.0/authentication/login`。

**正确示例**：
```bash
curl -X POST "http://localhost:8092/api/2.0/authentication" \
  -H "Content-Type: application/json" \
  -d '{"userName":"179537@qq.com","password":"Admin@123"}'
```

### 16.2 登录用户名

登录时可以使用以下任一方式：
- 用户名：`administrator`
- 邮箱：`179537@qq.com`

**均可成功登录**。

### 16.3 DocumentServer JWT Secret

DocumentServer 容器部署时设置的 JWT Secret 必须与 DocSpace 配置一致：

| 配置项 | 值 |
|--------|-----|
| `JWT_SECRET` | `DocSpace2024SecureJwtSecretKey123!` |
| `DocServiceSignatureSecret` | `DocSpace2024SecureJwtSecretKey123!` |

### 16.4 portalUrl 配置

`portalUrl`（来自文档服务的请求的协作空间地址）应该配置为：

```
http://onlyoffice-router:8092/
```

**不要使用**：
- `localhost`（DocumentServer 容器内无法访问）
- `http://onlyoffice-dotnet-services:5000/`（DocumentServer 需要通过 Router 访问）
