# 问题排查清单

## 概述

本文档定义了问题排查的标准流程和工作原则，确保问题能够被系统地发现、记录、解决和验证。

---

## 核心原则：端到端测试循环

### 工作流程

```
┌─────────────────────────────────────────────────────────────────────┐
│                     端到端测试循环                                   │
│                                                                     │
│  1. playwright-cli 端到端测试                                        │
│         ↓                                                           │
│  2. 发现问题 → 记录到"问题排查记录表"                                  │
│         ↓                                                           │
│  3. 分析根因                                                        │
│         ↓                                                           │
│  4. 解决问题                                                        │
│         ↓                                                           │
│  5. playwright-cli 端到端测试验证                                     │
│         ↓                                                           │
│  6. 问题解决？ ──否──→ 返回步骤2                                      │
│         │                                                           │
│        是                                                            │
│         ↓                                                           │
│  7. 关闭问题排查记录表                                               │
└─────────────────────────────────────────────────────────────────────┘
```

### 关键原则

| 原则 | 说明 |
|------|------|
| **测试优先** | 每次开始排查前，先用 playwright-cli 进行端到端测试，确认问题现象 |
| **记录为证** | 发现问题后立即记录到"问题排查记录表"，避免遗漏 |
| **循环验证** | 修复后必须再次端到端测试，确保问题真正解决 |
| **避免重复** | 如果测试发现问题仍然存在，继续在同一条排查记录中迭代 |

## 工具使用规范

### playwright-cli 命令行工具

```bash
# 1. 打开浏览器并访问目标页面
playwright-cli open http://target-page-url

# 2. 执行操作后获取页面快照
playwright-cli snapshot

# 3. 检查控制台错误
playwright-cli console

# 4. 检查网络请求
playwright-cli network

# 5. 截图保存
playwright-cli screenshot

# 6. 关闭浏览器
playwright-cli close
```

### 常用调试命令

```bash
# 获取页面标题
playwright-cli eval "document.title"

# 获取控制台消息
playwright-cli console

# 列出所有网络请求
playwright-cli network

# 查看元素属性
playwright-cli eval "el => el.getAttribute('src')" e15
```

## 问题记录规范

### 问题排查记录表模板

每个问题需要创建单独的排查记录文件，保存在 `/home/ubuntu/EasyDocs/DocSpace/docs/问题排查记录/` 目录下。

**文件名格式**: `ISSUE-XXX-问题简述.md`

**必要章节**:
1. 问题基本信息（编号、发现时间、类型、状态）
2. 问题描述（错误信息、涉及页面）
3. 排查过程记录（时间线）
4. 根因分析
5. 解决方案
6. 验证结果
7. 排查日志

### 记录时机

| 时机 | 记录内容 |
|------|----------|
| 发现问题时 | 错误现象、控制台输出、网络请求 |
| 分析过程中 | 代码追踪路径、关键发现 |
| 确定根因时 | 根因描述、影响范围 |
| 解决问题时 | 具体修改内容、修改位置 |
| 验证通过时 | 测试结果、截图证据 |

## 排查步骤清单

### 步骤1：端到端测试，发现问题

```bash
# 1.1 打开目标页面
playwright-cli open <目标URL>

# 1.2 执行触发问题的操作
playwright-cli click <element>

# 1.3 检查控制台错误
playwright-cli console

# 1.4 检查网络请求
playwright-cli network

# 1.5 截图保存
playwright-cli screenshot

# 1.6 获取完整页面快照
playwright-cli snapshot
```

### 步骤2：记录问题

创建问题排查记录表，包含：
- 错误信息（控制台输出）
- 网络请求详情（失败的请求）
- 页面快照
- 涉及的功能模块

### 步骤3：代码追踪

1. 找到前端入口代码
2. 追踪数据流向（前端 → API → 后端 → 数据库）
3. 找到关键转折点
4. 确定问题发生的位置

### 步骤4：分析根因

使用"5个为什么"分析方法：
- 为什么前端拿到了错误的URL？
- 为什么后端返回了内部网络地址？
- 为什么配置保存时使用了内部地址？
- ...

### 步骤5：实施修复

根据分析结果：
- 如果是配置错误 → 修改配置
- 如果是代码bug → 修改代码
- 如果是架构问题 → 提出架构改进方案

### 步骤6：端到端验证

```bash
# 6.1 重启相关服务（如有必要）
docker exec <container> <restart-command>

# 6.2 再次打开页面
playwright-cli open <目标URL>

# 6.3 执行相同操作
playwright-cli click <element>

# 6.4 检查是否还有错误
playwright-cli console
playwright-cli network

# 6.5 截图保存
playwright-cli screenshot
```

### 步骤7：关闭问题

如果测试通过：
- 更新排查记录表状态为"✅ 已解决"
- 记录验证通过的证据
- 总结经验教训

## 备注

- **避免循环论证**：每一步都要有实际的测试证据
- **避免重复排查**：如果已经在某条记录中排查过，更新记录而不是创建新记录
- **保存证据**：截图、日志、API响应等都要保存到记录中
- **闭环验证**：修复后必须验证，不要假设修复有效
